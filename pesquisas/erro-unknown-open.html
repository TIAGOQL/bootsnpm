inspeção de erro · Node · Windows

UNKNOWN · open

O script ia escrever um HTML. O Windows não deixou abrir o caminho. O resto da pilha é só o caminho até ali.

O golpe: writeFileSync na linha 32 de regenerate-posts.js tentou gravar:
posts\post-inspecao-expressao-templo-de-cristo-corpo-e-alma.html

O Windows respondeu: UNKNOWN · syscall: open · errno: -4094. Em português: “não consegui abrir esse arquivo; não te digo o motivo clássico (ENOENT, EACCES).” No Desktop isso costuma ser pasta posts ausente, arquivo aberto no editor, ou OneDrive segurando o ficheiro na nuvem.

Não é: o vilão Module.load. Essa linha só diz que o Node estava a carregar o teu script. A causa está em open + o path.

Palavras da pilha

Error
erro — algo falhou
UNKNOWN
desconhecido — o Windows não mapeou para um código amigável
open
abrir (o ficheiro, para escrever)
writeFileSync
escrever arquivo e esperar — sincrono: o script para até gravar
anonymous
função sem nome no script — não é o grupo Anonymous
Module.load / loader
o carregador CommonJS a correr o teu ficheiro — porteiro, não a causa. Ver palavras do stack.
errno / code / syscall / path
número do erro · código · chamada ao sistema · caminho do ficheiro

O que fazer (aí no PC)

1. Ver se a pasta ProjectBudGanja\posts existe. Se não, criar.
2. Fechar o HTML se estiver aberto no Cursor / VS Code.
3. Se o Desktop está no OneDrive: pasta “manter sempre neste dispositivo”, ou copiar o projeto para fora da nuvem e correr de novo.
4. Voltar a correr o script.

No REM: o visitante do painel não executa isto. Só quem roda Node no terminal. Perto de Module.load e de GitHub. O N=1 continua no aparelho: dados.
